## 1. 项目目标与当前状态

改进三在 CompressAI 的 Hyperprior 图像压缩模型上加入可学习的 Gain 调制，实现**单模型、多码率、连续插值、真实编码与解码**。用户通过 `position` 参数在不同 Gain 档位之间切换或插值，从而调节整体码率（bpp）。此外，提供目标 bpp 搜索以及 ROI/σ 简化联合压缩原型，便于后续对接 Customized 的 LMA/CVA。

当前完成的是**功能验证及交接原型**：Kodak 24 张图像 × 9 个位置，共 216 组连续 Gain 编解码；已验证 Kodak 平均码率约 0.0686～0.1843 bpp。小规模 Gain 训练仅运行 8 步，不能将当前权重视为充分优化后的正式模型。ROI/σ 联合接口不等同于完整复现 Customized LMA/CVA。

## 4. 环境与运行方式

### 4.1 推荐环境

已验证的运行环境为 **Windows 电脑上的 WSL2 Ubuntu + Python 虚拟环境 + PyTorch + CompressAI + CUDA**。Windows 上使用 VS Code 没问题：通过 WSL 扩展连接后，仍可在 VS Code 中编辑、调试。

**Windows 原生 Python 尚未完成实际编解码验证。** 由于 CompressAI 的熵编码模块涉及编译扩展，不应把 `pip install compressai` 成功等同于全链路运行成功。组员可先尝试 Windows 原生 Python；若 CompressAI 安装或实际熵编码失败，推荐通过 VS Code Remote-SSH 使用现有 Linux 运行主机，或用 WSL2。无需修改核心 Gain 算法。

### 4.2 基础依赖

核心功能使用：`torch`、`compressai`、`numpy`、`Pillow` 等；文本引导掩膜流程额外使用 `transformers`、`safetensors` 及相应 CLIPSeg 组件。曾使用的 CompressAI 为 1.2.8。其余版本以实际可运行环境或仓库依赖声明为准，不建议随意升级后直接假定结果一致。

在项目根目录运行时，可按运行方式配置 `PYTHONPATH=.`；Windows PowerShell 相应设置为 `$env:PYTHONPATH = '.'`。

## 5. Gain 核心模块用法

### 5.1 关键概念

- `position`：连续控制位置，取值范围 **0～3**；0、1、2、3 分别对应四个 Gain 档位，非整数值采用插值。
- `gain_at(position)`：计算相应位置的 Gain。
- `compress_at(x, position)`：输入图像张量并执行真实熵编码，返回编码结果。
- `decompress_at(encoded)`：由配套编码结果解码重建图像。
- 典型输入 `x`：`[1, 3, H, W]` 的 RGB 张量，像素值在 `[0,1]`，并满足模型要求的图像尺寸与设备配置。不要将示例中的任意尺寸都视为已验证。

### 5.2 checkpoint 与模型初始化

Gain checkpoint 位于 `checkpoints/gain/gain_small_trained.pth`，包含模型需要恢复的状态。**具体保存字典键、初始化参数应以 `trainable_gain_hyperprior.py` 及相应训练/加载脚本为准**；不要在未核对 checkpoint 结构时擅自假定键名。

对接方推荐直接参考项目已有的模型加载与评测脚本，复用其初始化和 `load_state_dict` 逻辑。模型加载完成后应切换到 `eval()`，并按实现要求准备熵编码表（例如必要时调用 `update()`），再进行真实编解码。

### 5.3 接口示例（仅展示调用逻辑）

```python
# model 是已用仓库权重正确初始化、切换为 eval 的 ContinuousGainHyperprior
# x 是设备一致的单张 RGB 张量 [1, 3, H, W]
encoded = model.compress_at(x, position=1.5)
recon = model.decompress_at(encoded)
x_hat = recon['x_hat']
```

此段不是可独立执行的全量脚本，实际运行还须根据本仓库模型创建方式加载权重与图像。

### 5.4 目标 bpp

```python
# controller 是用已加载的连续 Gain 模型构建的 RateController
encoded = controller.compress_to_target(x, target_bpp=0.10)
```

这是功能入口示意；**返回对象细节以 `rate_controller.py` 中实际实现为准**。目标 bpp 仅在当前模型可达到范围内搜索，并非保证任意目标精确匹配。

## 6. ROI + σ 联合原型与苏致远的接口

### 6.1 输入输出

主要接口：

```python
encoded = model.compress_joint(x, mask, position=1.5, sigma=0.3)
recon = model.decompress_joint(encoded)
x_hat = recon['x_hat']
```

- `x`：单张输入图像张量，通常 `[1,3,H,W]`。
- `mask`：ROI 掩膜，已知接口使用 `[1,1,H,W]`，与图像空间对齐。
- `position`：整体码率 Gain 控制量，0～3。
- `sigma`：区域调制控制量；简化适配使用 `(0,1]`。
- `encoded`：包含压缩数据和解码所需附加信息，简化原型会携带 ROI 掩膜的 PNG 表示。

### 6.2 简化公式及边界

简化 Customized 风格调制：`A(M, σ) = M + (1-M)σ`，ROI 区域权重为 1，背景按 σ 调整，再与全局 Gain 配合使用。**此实现并非 Customized 原始 LMA/CVA 的完整复现**，不能作为正式算法正确性或性能结论。

苏致远负责的正式 LMA/CVA 可能具有不同潜变量变换、重要性建模与熵模型流程，实际集成不保证仅换一个函数即可完成。建议他先确认双方潜变量形状、调制插入位置、编码侧信息与解码恢复方式，再决定复用完整 Hyperprior 原型还是迁移 Gain 调制方法。

## 8. 推荐交接顺序

1. **获取项目与权重**：克隆 `feature/variable-rate-gain`，确认 `continuous_gain.py`、`trainable_gain_hyperprior.py` 和 `checkpoints/gain/gain_small_trained.pth` 存在。
2. **验证核心 Gain**：按项目现有测试脚本加载权重，对同一张图运行不同 `position`，检查真实码流可解码、重建尺寸正确、bpp 有变化。
3. **再对接正式 LMA/CVA**：参考 `roi_gain_joint.py` 和 `customized_gain_adapter.py` 的输入输出协议；不要把简化 σ 公式当作正式 Customized 实现。
4. **协同训练与验收**：正式网络适配后，协同确定损失函数、训练策略和对比实验；当前 8 步 checkpoint 仅用于功能验证。

## 9. 常见问题

**Q：只克隆 GitHub 就能运行吗？** 不能完全保证。源码和 Gain 权重已包含，但仍需配置 Python/CompressAI 环境、准备输入图像；完整 CLIPSeg 流程还需要单独模型资源。

**Q：VS Code 必须安装 Linux 吗？** 不必须。VS Code 可以直接在 Windows 使用；但 CompressAI Windows 原生编译及真实编解码兼容性尚未验证。可优先试 Windows，失败时使用 VS Code 远程 Linux/WSL。

**Q：为什么 `.pth` 重要？** `.py` 定义网络结构和计算逻辑；`.pth` 保存实际模型参数，二者配合可复现已测试的模型状态。此 checkpoint 是小规模训练的功能验证版本。

**Q：苏致远可以直接把 `.pth` 加载到 Customized TIC 吗？** 通常不能假定兼容。此权重对应 Hyperprior 网络及 Gain 参数；正式 Customized TIC 的结构不同，可能需要迁移 Gain 方法并重新训练。

**Q：σ 是否已完成？** 已实现简化联合调制和编解码原型；**正式 Customized CVA/LMA 仍需由相应负责人完成集成验证**。
